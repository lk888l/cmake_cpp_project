# 灰度、framebuffer 与渲染细节

**中文** | [English](grayscale-and-rendering_en.md)

## 1. SSD1306 为什么没有真实灰度

SSD1306/SSD1315 的目标配置是 128×64 单色 framebuffer。每个像素在显存中只有一个 bit：0 为熄灭，1 为点亮。控制器的 contrast 命令改变整体驱动强度，不能给同一帧中的每个像素设置不同亮度。

本工程接受 0～255 intensity，是为了给业务提供统一的“视觉亮度”接口，然后把中间值转换为空间密度不同的黑白点阵。它不会改变硬件像素位深。

## 2. 4×4 Bayer 空间抖动

当前矩阵为：

```text
 0   8   2  10
12   4  14   6
 3  11   1   9
15   7  13   5
```

intensity 先转换成 0～16 的覆盖等级：

```text
level = (intensity * 16 + 254) / 255
```

像素 `(x, y)` 在 `matrix[y mod 4][x mod 4] < level` 时点亮。因此：

- intensity 0：0/16 点亮。
- intensity 约 64：约 5/16 点亮。
- intensity 128：9/16 点亮。
- intensity 约 192：约 13/16 点亮。
- intensity 255：16/16 点亮。

矩阵与绝对坐标绑定，同一强度每帧得到相同图案，不会像时间 PWM 那样闪烁，也不需要额外刷新带宽。

## 3. 视觉特性

空间抖动的优点：

- 单帧静止，不依赖严格帧率。
- 仍只传输一个 1-bit framebuffer。
- Linux、ESP32 和 STM32 得到确定一致的像素图案。
- 很适合进度条、阴影、背景分区和小型灰度图标。

限制：

- 4×4 重复纹理在 0.96 寸近距离观看时可见。
- 细线和小字号文字的中间灰度可能显得断裂。
- 面板颜色、视角和像素间距会影响“感知亮度”。
- 空间抖动不能等同于 SSD1327 等 4-bit 灰度控制器。

对于关键文字、边框和告警图标，推荐使用 255；中间 intensity 更适合作为大面积填充、次要文字或装饰层级。

## 4. framebuffer 布局

U8g2 全缓冲模式为 1024 B。SSD1306 按 page 组织，每页覆盖 8 行，128 列：

```text
page 0: y = 0..7,   128 bytes
page 1: y = 8..15,  128 bytes
...
page 7: y = 56..63, 128 bytes
```

业务不应依赖该布局直接写内存；使用 `OledCanvas` 可自动处理旋转和裁剪。原始 framebuffer 访问只用于测试、抓图或实现经过验证的高性能特效。

## 5. 绘图模式

### 替换式图案

像素、线、填充图形调用 `drawPixel()` 时，会根据 intensity 决定把目标像素设为 1 或清为 0。因此中间灰度填充覆盖旧内容，而不是仅在旧 framebuffer 上做 OR。

这意味着后画的灰度填充可以清除前景。页面应按“背景 → 大面积填充 → 图标和文字 → 强调边框”的顺序绘制。

### 透明文字

文字处理不同：先保存原 framebuffer，再用 U8g2 透明字体绘制全亮 glyph，最后只对“本次新增的像素”应用 Bayer 筛选。未被 glyph 覆盖的背景不改变。

如果要刷新动态文字，推荐每帧先清屏或清除文字所在矩形，否则新字符串不会自动擦除旧字符串超出的部分。

## 6. 位图格式

### XBM 1-bit 位图

`drawBitmap()` 使用 XBM LSB-first 数据。可将黑白图标导出为 XBM，再把数组作为 `const uint8_t[]` 编译进程序。数据每行按 `ceil(width / 8)` 字节排列。

### Gray8 位图

`drawGrayBitmap()` 的每个输入像素占一个字节。示例：

```cpp
constexpr uint8_t gradient[8] = {
    0, 36, 72, 108, 144, 180, 216, 255
};
canvas.drawGrayBitmap(0, 0, 8, 1, gradient);
```

函数会对每个像素执行边界检查和 U8g2 写操作，优先保证可移植性与确定性。整屏灰度图每帧转换需要处理 8192 个像素；若 MCU 需要动画，应预先把静态资源离线抖动成 XBM，或增加批量 framebuffer 转换器。

## 7. 文字与字体体积

U8g2 支持 UTF-8 解码，但字体决定实际 glyph 集。当前四个字体以 ASCII/数字为主。加入中文时有三种策略：

1. 选用 U8g2 现有中文子集字体，开发快但 Flash 可能较大。
2. 用 U8g2 字体工具生成产品实际使用字符的子集，最适合 MCU。
3. 将少量固定中文标题制作成 XBM 图标，不提供动态文本能力。

无论采用哪种方式，都应保留 `-fdata-sections` 和链接器 `--gc-sections`，并通过 map 文件确认最终链接了哪些字体，不能只根据 `u8g2_fonts.c` 源文件大小判断固件占用。

## 8. 刷新带宽

400 kHz I²C 每 bit 理论时间为 2.5 µs。1024 数据字节至少需要约 8192 bit，考虑 ACK 后约 9216 bit，即约 23 ms；加上命令、控制字节、系统调用或 HAL 开销后会更长。

可参考的刷新策略：

- 1～10 Hz：监控面板、菜单、传感器数字，余量充足。
- 20～30 Hz：简单动画可行，需要测量总线占用和任务抖动。
- 更高帧率：优先 SPI、局部刷新或降低更新区域。

空间灰度不会成倍增加刷新次数；时间灰度则至少需要多个子帧，因此本工程没有采用时间灰度。
